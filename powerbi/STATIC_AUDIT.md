# Power BI source audit — 31 October 2026

The audit reviewed the generated Power Query, DAX, TMSL model, and PBIR visual queries beyond JSON-schema conformance. Native Desktop/engine/render execution remains pending.

| Severity | Finding and evidence | Resolution |
|---|---|---|
| P2 | `COUNTROWS` returns BLANK for an empty table. The original coverage numerator therefore returned BLANK when a nonempty interval subset had **zero** covered observations; the correct result is0%. | Normalize only the coverage numerator with `COALESCE(…,0)`; keep the no-interval denominator blank so coverage without intervals remains BLANK. The real-data context fixture includes a singleton uncovered observation. |
| P2 | Nonchampion expected exports contained interval-count0 while DAX `COUNTROWS(empty)` returned BLANK. The same ambiguity affected empty scored subsets. | Count measures explicitly normalize empty counts to0. The outer one-model guard still returns BLANK for no/multiple/zero model contexts. Accuracy and energy measures retain BLANK when there are no scored pairs. |
| P2 | PBIR charts and tables omitted explicit category/time sorting; model sort-by metadata alone did not pin the visual query's requested order. | All chart categories and table keys now sort ascending in PBIR. Static validation checks the actual query definition. |
| P2 | Keyboard tab order used `x+y`, which could visit a lower chart before controls farther right in the preceding row. | Tab order now follows `y*10000+x`, giving top-to-bottom, left-to-right order. Bounds, unique names, references, and tab order are checked statically. Title-based alternative text is supplied; human accessibility review remains required. |
| P2 | Regeneration silently substituted a frozen training threshold if `outputs/run_summary.json` was missing. | Regeneration requires the actual run summary and fails clearly if it is unavailable. This prevents silently pairing a stale threshold with a changed run. |

Retained correct behavior: observed history sums only `FactDemand`, so models cannot multiply historical energy; invalid actuals stay null; scored metrics require both actual and forecast; all test metrics explicitly restrict the test split; model selection uses the dimension cardinality; date filters flow from the shared UTC date dimension to both facts; local pattern columns are derived by Python's timezone conversion; forecast lines use a single Y role; comparison-table interaction ignores the model slicer; future data has no observed actual.

Relationship cardinality and active status are now explicit many-to-one and active, with one-way dimension-to-fact filtering. These metadata values agree with Microsoft's [TMSL relationship definition](https://learn.microsoft.com/en-us/analysis-services/tmsl/relationships-object-tmsl?view=asallproducts-allversions). The blank/count fixes follow Microsoft's [COUNTROWS](https://learn.microsoft.com/en-us/dax/countrows-function-dax), [COALESCE](https://learn.microsoft.com/en-us/dax/coalesce-function-dax), and [DIVIDE](https://learn.microsoft.com/en-us/dax/divide-function-dax) contracts.

Verification completed: 45 PBIP/PBIR files passed official cached Microsoft schemas; static checks cover measure guards and nonblank filters, typed field references, explicit cardinality, category sorts, shared-axis roles, layout bounds, alt-text presence, row-major tab order, and comparison interaction. Export reconciliation verifies the current 61,368-hour history and 131,544 forecast rows and matches the champion and high-demand values to the Python run summary. Twelve independent expected filter contexts and four read-only native DAX queries were generated.

The expected-context CSV and the primitive query are not engine execution. No native-result receipt, refreshed PBIX, or Power BI screenshots have been invented. The next required evidence is actual native query exports and the refreshed report screenshots described in `NATIVE_ACCEPTANCE.md`.

A subsequent robustness check added the guarded `Test High Demand Coverage 80` measure and a diagnostic card. Its denominator includes only scored high-demand test pairs with both valid interval bounds. The expected-context suite includes an uncovered high-demand singleton, so the required result is0% rather than BLANK; nonchampion/no-interval and no/multiple-model contexts remain BLANK. The displayed card evaluates the current model/date context; there is no hardcoded coverage claim in the report canvas.
